### YumCut

**核心提炼**
- 解决什么问题：想批量做竖屏短视频但不会剪、没时间剪——一句话想法直接变成可发布的 9:16 成片（脚本、配音、画面、字幕自动拼好）。
- 核心用法（4 步）：1) 自部署或直接用托管版 → 2) 输入想法/主题 → 3) 系统自动生成脚本→配音→画面→字幕 → 4) 导出成片发 TikTok/Reels/Shorts；支持多语言、批量渲染，也有 API 供 agent 调用。
- 什么时候用 / 常见坑：适合无真人出镜账号、日更测选题的场景；个人用免费，想拿它给客户做商用服务需要另购商业授权；自部署要自备模型服务，成本自己控制。

**适用场景**：想低成本批量起竖屏账号的个人、代运营团队、带 agent 的内容流水线。

**怎么用它搞钱**：带货短视频代运营。

### cutcli-cookbook

**核心提炼**
- 解决什么问题：手调剪映草稿慢、AI 写剪辑逻辑没法落地——用命令行/JSON 直接生成剪映草稿，桌面版打开就能继续手改。
- 核心用法（4 步）：1) `curl -s https://cutcli.com/cli | bash` 安装 → 2) 套 examples/ 或 templates/ 的 JSON 模板 → 3) `cutcli draft create` 等命令生成草稿 → 4) 打开剪映桌面版，草稿已在列表里，微调后导出；也可以把 prompts/ 丢给 Cursor/Claude Code，让 agent 驱动剪辑。
- 什么时候用 / 常见坑：剪映系模板化剪辑、口播批量生产时用；依赖剪映桌面版；云渲染要配 API key。

**适用场景**：会用 Cursor/Claude Code、想把剪辑变成代码流程的剪辑师和 agent 开发者。

**怎么用它搞钱**：剪辑外包 / 模板卖课。

**来源**：[xuliang2024/cutcli-cookbook](https://github.com/xuliang2024/cutcli-cookbook) · ⭐198 · 更新于 2026-05-26

### FireRed-OpenStoryline

**核心提炼**
- 解决什么问题：手动剪辑太慢、AI 一键成片又没法细改——用自然语言指挥剪辑（"把这段删掉""换个卡点音乐"），每一步可见、可改。
- 核心用法（4 步）：1) 装好（Python ≥3.11，有 OpenClaw/Claude Code 的 skill）→ 2) 上传素材、说清意图 → 3) agent 自动搜素材、写脚本、配音配乐加字幕 → 4) 对话式逐轮改（剪、换、重排），满意后导出；调好的工作流可存成 Skill，换素材批量复用。

**适用场景**：想对话式剪辑、批量产出统一风格视频的个人创作者和小型团队。

**怎么用它搞钱**：接短视频代运营/批量带货视频单——一次建好 Skill，多客户复用。

### @zhu185178：Opus 5.5 当导演跑通 AI 短剧（挑片与可追溯流程）

**核心提炼**（聚焦挑片/审片环节）
- 让模型先反问再干活：把 1500 字剧本交给模型，它先建项目文件、再追问用途/平台/画风/预算/质量 5 个问题——"先反问后出活"这套逻辑自搭 harness 也能照搬。
- 画风三选一并排看：同一场戏先出 3 张不同画风样图（真人古装、3D 国漫、2D 国风）并排选，避开对"电影感"这类词的理解偏差。
- 角色一致性配方：每个角色一张图里放三视图（胸像特写+全身正面+全身侧面）再加一个辨识特征，解决换镜头换脸。
- 片名字不出错：只靠提示词描述会出假字，首尾帧图片约束让片名四个字一笔不错。
- 挑片两阶段：每段生成 3 条候选，先过硬指标（脸像不像、台词对不对、音量合不合），再谈审美。
- 全程可追溯：每段能看到候选条数、选中哪条、提示词、参考图、首尾帧，方便复盘重做。
- 算总账：全片约 106 美元（文生图和配乐订阅未计入）；单价便宜不等于总价便宜，看整片总账。

**适用场景**：用 AI 生成+人工挑片做短剧/系列短片的个人和团队。

**怎么用它搞钱**：短剧代工的"AI 制片"服务——一次跑通流程，多剧复用。

### @yang_xin19：口播+AI 剪辑涨粉账

**核心提炼**
- 拆开看全流程：选题剧本→拍摄出镜→剪辑（Agent 擅长的脏活：去废词、压停顿、微调语速、推镜、字幕节奏）→包装（B-roll、数据卡片、音效），包装 AI 只能给草案，记忆点得自己定。
- 正确归因："6 分钟剪完"只是剪辑耗时，不是做号总成本——案例博主已稳定更新 3 个月、主页有 5 条爆款打底。
- 不绑一家的口播流水线：粗剪交给规则（去废词、压停顿、自动上字幕），精修留给判断（梗图、何时抛观点留人工）；具体工具只是第三步的可选引擎。
- 发完复盘三个数：点击差→改封面标题；完播差→改节奏和前 15 秒；收藏高→下条把方法写更清楚。

- 决策逻辑：瓶颈是素材堆着剪不动→上 AI 剪辑；瓶颈是出镜和选题→先练镜头。出镜和选题定流量上限，工具把时间成本打下来。

**适用场景**：口播账号、想量化剪辑投入产出比的博主。

- 解决什么问题：做一条历史/人物故事短视频要经历写稿、配音、对时间、画风统一、剪映推拉，单人一天只能做一条——一句话给 Agent，走"选题策划 → 3 秒黄金钩子 → 爆款正文 → 豆包配音 → 本地毫秒级字音对齐 → 3 套画风分镜生图 → 自动导出带推拉运镜的剪映专业版草稿"全链路。
- 核心用法：1) 文案基于 370+ 篇爆款逐字稿蒸馏出历史叙事风与真实人物故事风；人物故事风节奏为钩子先行 → 巅峰数字 → 可谁也没想到 → 磨难场景 → 金句收尾；钩子库含 A 型数字连排、B 型宿命定格、C 型反常画面等五大类；选定钩子后按事实核查表与字数约束输出，字数误差控制在 ±5%；作者实测更喜欢 Claude Opus 4.6 与 Gemini 3.8 Flash 的文案，尤其 Gemini 3.8 → 2) 配音与对齐：推荐豆包语音大模型，走火山引擎 V3 双向流式 WebSocket 协议，支持 seed-tts-2.0 与声音复刻音色，Agent 用 ffprobe 校验完整性防缺字漏字、文本做哈希防重复扣费；也可自备 voice.mp3；无论哪种音频，都用本地离线工具 Coli（基于 sherpa-onnx）做毫秒级转录，提取每句起止时间戳并对照原文纠偏人名、专有名词 → 3) 分镜 Audio-First：先音频后分镜，以转录时间戳为基准，默认约 8 秒/图，确保从第 0 帧就有图且画面与当时口播情节对应；逐镜做时代考据（人物年龄阶段、时代服饰、发式、建筑形制）；三套画风为 historical-comic（厚涂历史漫画风）、monochrome-narrative（黑白纪实叙事风）、historical-realism（历史写实风）；用正文基准参考图库注入生成工具，首张核验笔触与明暗对比后再批量出图以降低画风漂移 → 4) 剪映草稿：基于 pyJianYingDraft 全自动写入轨道，图片与音频自动复制进剪映草稿目录；平滑慢推拉默认约 16–20 秒走完 12% 幅度；切点冲击缩放为出镜微推近 1.28x 与进镜拉回 1.50x 关键帧，避免剪映自带转场闪黑帧；打开剪映可直接播放、微调、导出 4K/1080P → 5) 字幕：Skill 内未配置带字幕功能，作者强烈建议在剪映里识别字幕，理由是省心且可控。
- 本地复测补充（@superfang119，固定仓库提交 ee25a75，走"自备音频"分支，未测豆包语音与三套画风横向对比）：本地 IndexTTS2 生成配音（单声道、22050Hz、20.262 秒），Coli 转录，imagegen 生成三张厚涂画面，再交给原仓库草稿导出脚本；画面不按总时长除以三均分，而是跟转录结果在"任何人"后取 8.04 秒、在"河边"后取 11.22 秒，三镜为 0–8.04 秒桥头送信人、8.04–11.22 秒藏信近景、11.22 秒以后无人桥头；第二镜只有 3.18 秒，因此关闭该镜的切点冲击缩放，保留简单推拉；方法结论是先定声音再排画面，能回答"这张图为什么在这里换"，但时间戳写到毫秒不代表识别误差只有一毫秒，转录可漏词、错字、错断句，需把识别文本与定稿核对再用对应词句定切点；关键故障是第一次转录包装调用在输出解析阶段报错停住，恢复时保留报错、另存 Coli 实际返回的结构化识别结果，再走原脚本已有的"导入 ASR JSON"入口继续，没有改成按字数估时间，也没有用手写字幕冒充 Coli 结果，作者明确不把这次恢复写成"兼容问题已彻底修复"；参考图结论是三张图都实际传入仓库 HC02 厚涂参考，后两张还另外传入第一张图以延续衣服、信封与河镇气氛，但第一镜与第三镜对比时城门左右位置发生变化，第三镜虽实现"桥头无人"，空间关系只是近似延续，第一张为浓烈夕照、第三张要求晨光但实际仍偏暖亮色，不一定能立即读懂已过一夜，下一轮应先固定桥、城门与河流位置关系，再比较相同构图的日暮与清晨；草稿与预览分开验收：草稿导出脚本用 pyJianYingDraft 把图片与音频复制进工程，按同一份分镜计划写轨道与运镜，价值在于保留可继续修改的工程交接，本地预览渲染得到 1080×1920、30fps、608 帧的 H.264/AAC 视频约 20.267 秒、完整解码检查通过、草稿导出无警告、视频包含音轨，但 FFmpeg 能出视频不等于剪映桌面版已成功打开或导出，本次未完成剪映界面人工打开验收，也未完成独立人耳听审，音文核对与音轨存在检查不能替代读音与听感验收；可复用建议是先用一小段自己的定稿与配音跑出带真实时间戳的分镜，再生成少量图，先确认音文、图意与空间，再扩到长片，有现成素材时也可只开草稿阶段，第一次就做长传记、几十镜、克隆声音、挂车时，出问题很难定位。

### 配音即时钟：先配音、再算每字时间、画面卡词

**核心提炼**
- 解决什么问题：先剪画面再配音、再一点点对，越对越错位——反过来：稿子写好后先生成整篇配音，配音里第几秒说什么就是整条视频的时间表，字幕与画面全跟着它走。
- 核心用法：1) 强制对齐：算出每个字从第几秒开始、到第几秒结束；做法有三种：配音模型自己返回时间、用专门对齐模型算、都没有时把配音拖进剪映用字幕识别（但导出字幕文件要开会员）；作者推荐千问 Qwen3-ASR，0.6B 参数，一张 4G 显存显卡可跑，且已做成 MCP 供模型直接调用 → 2) 画面生成规则：有了每字时间后交给大模型一句一句读稿子，讲数据做图表、讲步骤做流程、引用原话截真网页并划荧光笔、提到产品放 logo；每个动画写成"说到某个词的那一刻，某个东西出现"；画面没有一帧是边播边录的，全按时间一帧一帧算出来，60fps 时第 600 帧画第 10 秒的样子，画完再把配音放回去，电脑卡一下也不会错位 → 3) 导出规格：画面 1920×1080，每秒 60 帧，动画写成一个网页 `产物/动画.html`，网页里提供一个函数 `renderAt(秒)`，传入任意时间就画出这一刻的画面，不要让页面自己往前播放 → 4) 实操文件：文件夹放四份文件——稿子、读法规则、配音设置、画面要求，对话框里只说大白话；实操演示用 DeepSeek + DeepSeek Harness，做一条 15 秒"为什么天空是蓝色的"科普动画；配音设置示例为 ElevenLabs、模型 eleven_v4，API key 放在同一文件夹的 key.txt 里，不要打印出来也不要写进代码文件；作者 key 文件忘填时，Agent 读到空文件后停下来问 key 怎么给，没有接着乱跑。
- 配音选择：不推荐自己录（录音、重录、剪气口、降噪门槛高）、不推荐全网通用机械音（观众记不住、易成营销号）、不推荐克隆别人音色（不花大量时间训练一听就是 AI）；推荐直接选平台自带音色，省时间、效果不差、方便接进 AI 工作流；国产有豆包、千问、MiniMax，开源有 Qwen3-TTS、IndexTTS，作者自己用 ElevenLabs；建议用 API 而非网页生成，因为停顿、情绪、长句断句可由 AI 写进请求，一次生成想要的样子。
- 挑音色方法：Agent 听不到声音，做法是先在平台六万个音色里按中文、女声筛出 60 个，再挑 10 个真的生成一遍，测每个声音的音高与语速，最后把生成声音识别回文字看吐字清不清楚；最后给出四个候选并写语速、音高与特点，作者在备选里挑中了更喜欢的一个，结论是 AI 缩小范围、最终仍要自己听。
- 配音验收：定下音色后先按读法规则改稿，只改了一处——"铺满"换成"布满"，因为"铺"是多音字可能读错；生成完再把配音识别一遍与稿子逐字比对，65 个字全部对上。
- 画面验收教训：第一版画面很空，只有一个小点与几根细线，改一次仍不行，整条就是一个太阳在发光；问题在于只说"好看一点"，Agent 不知道什么叫好看，只会加光效；换成给一份美术分镜（风格、颜色、每个镜头画什么、画多大、卡在哪个字上）并推翻重做；结论是把想要的样子写成它能照着做的规格。
- 什么时候用 / 常见坑：读法规则示例——型号里的数字写成汉字前后留空格（如 GPT-6 写成"GPT 六"）、普通数字保持阿拉伯数字、容易读错的多音字换意思一样的词、两个标点之间超过 26 个字按意思加逗号换气、段落之间空一行读的时候停得久一点；字幕用原稿原文去掉标点，一条字幕是一个短句、在逗号句号处换条、一条不超过 14 个字，每条字幕的出现和消失都卡在时间表里那句话真实开始和结束的时间。

**适用场景**：做科普、讲解类动画短视频，想让字幕与画面精确卡在词上的个人创作者。

**怎么用它搞钱**：接科普/知识动画代制作——"配音即时钟 + 逐词卡点"是一套可报价的流程，按秒或按条收费；或做成自己的科普账号矩阵。

### 代码即影片：TypeScript 故事板 + GSAP + 帧同步音效

**核心提炼**
- 解决什么问题：After Effects 工程改一处就要重做一遍，版本一多就乱——没有 AE 工程，每一帧都是代码：一部片子就是一个文件——故事板，每个场景是几行数据。
- 核心用法：1) 场景为 TypeScript 模块，构建普通 DOM 并用 GSAP 做动画，使用与品牌其余部分相同的缓动曲线 → 2) 浏览器内实时运行，改一行预览就更新，可 scrub 到任意帧；渲染时 Playwright 在无头 Chrome 中打开影片，按一帧一帧推进时钟，把每一帧交给 ffmpeg；示例为 60fps 下 2022 帧，同一份代码可出 1080p 或 4K → 3) 声音也是代码：场景不直接播放音频，而是放置 cue，例如按键声、Agent 流式输出文字时的 tick 声、支付落地时的 tap 声；每个 cue 都是真实录音，离线与帧同步混音；音乐的放置要让最大高潮落在 logo 上 → 4) 与 Claude Code 的协作方法：不写大部分手写代码，而是指导 Claude Code，关键是喂给它"品味"而非指令，例如给它一个喜欢其节奏的参考片段；评审时像设计评审一样提意见，例如"这感觉像有人在点按钮""不要 whoosh 音效""绝不凭空发明颜色"；每条意见都变成它跨会话保留的规则；作者明确表示没有使用任何 Claude skills → 5) 改动成本：改动很便宜，换片中课程只需改一个常量再重新渲染；影片变成像代码一样可编辑的东西，而不是重做。
- 什么时候用 / 常见坑：作者自述这样一部片子约 2 小时工作量、约 60 次调整提示，一条 1 分 30 秒影片的完整 4K 60fps 渲染约 6 分钟，均为作者自述、未独立验证；适合讲解、产品演示类，不适合要真人实拍质感的片子。

**适用场景**：会用 Claude Code、做产品发布片/讲解片、需要反复改版的创作者和品牌团队。

**怎么用它搞钱**：接产品发布片、讲解片代制作——"改一处只改一行再渲染"是报价优势，按改几轮报价，不按生成几次报价。

### CapCut × ChatGPT/Codex：对话式剪辑三轮试跑法

**核心提炼**
- 解决什么问题：有素材不会剪、没时间学剪辑软件——CapCut 公布了面向 ChatGPT 的新插件，从聊视频想法到制作可编辑草稿，再用对话继续改镜头、字幕与音乐，最后进入 CapCut 编辑器精修；但官方发布新闻稿仍把更完整的对话式剪辑体验描述为接下来几个月推进，具体能否使用、开放哪些功能要看账号、地区与版本，不能理解为所有手机端、网页端用户都已可用。
- 核心用法：1) 能力按任务选：已有素材时上传素材或现有草稿组织成片、调整镜头顺序与长度；只有想法时描述主体、动作、风格与画幅生成图像、视频素材并逐步形成草稿，商品外观、人物一致性仍要检查；想找现成样式时按故事用途、风格与节奏找 CapCut 模板再替换媒体继续修改；初稿已做好时继续处理字幕、文字出现时间、配乐、转场与效果，且一次只改清楚一件事以便核对 → 2) 安装与连接检查：官方页面标题用 CapCut × ChatGPT，导航与工作流说明里也用 CapCut × Codex，当前安装说明指向桌面端 Codex 任务，找入口时两个名称都要认清；步骤为在电脑上打开官方产品页 https://www.capcut.com/tools/capcut-x-codex，找到安装提示点 Copy 复制，在桌面端 Codex 任务中粘贴并按当时页面流程完成插件安装，再按提示连接并授权自己的 CapCut 账号——安装完成与账号授权是两个步骤；安装、授权结束后在新任务里确认工具是否可用再开始制作 → 3) 连接验收指令示例："请检查当前 CapCut 插件的连接状态，并列出这个任务实际可用的功能。若支持模板检索，请先检索适合 20 秒旅行短片的模板。暂时不要生成素材或创建视频草稿。"只回复"我可以帮你剪视频"不能证明连接成功；安装失败处理安装，授权失败处理连接，授权成功但当前任务没有工具时先新建任务再检查，不要一上来反复重装 → 4) 第一轮试跑：用自己熟悉的旅行素材做一条约 20 秒、9:16 的社交平台短片，开头放最能交代地点的镜头，中间展示活动，结尾保留一段完整风景画面，只用提供的素材；先给出选片与顺序方案，确认后再制作可编辑草稿与预览，无法读取的素材要明确列出；目标是得到能继续改的项目，只有一份脚本时还不算完成这一步 → 5) 第二轮局部修改示例："在刚才的草稿上，把第二个镜头缩短 1 秒，结尾风景镜头相应延长 1 秒。其余镜头顺序、字幕和配乐保持不变。请返回修改后的预览。"不要只看视频是否仍为 20 秒，还要看被要求保留的部分有没有跟着变化，以此判断后续修改适合继续对话还是直接手动调 → 6) 第三轮编辑器衔接示例："请提供打开当前草稿继续编辑的入口，并列出还需要我检查的问题。我会在 CapCut 中核对字幕、声音和裁切，再决定导出。"打开后检查素材有没有丢失、时间线能否继续改、竖屏有没有裁掉主体；导出分辨率、帧率与可用选项以当前界面为准。
- 什么时候用 / 常见坑：经常把现成素材剪成门店短片、产品演示、旅行记录或活动回顾的人，可优先试选片、排顺序与初稿修改，判断依据是交回来的草稿是否愿意继续往下改；已进入逐帧卡点、复杂合成、精细声音处理的工作，建议比较两种操作成本——一句话能说明白的修改交给对话，拖一下就能完成的细节直接打开编辑器处理；官方产品页提到免费体验入口，但未完整列明全部能力的额度与收费边界，使用生成、素材或导出选项前要查看实际界面，不要推断全部操作无限免费；本条收的是"安装 + 连接验收 + 三轮指令"的试跑法，同期纯新闻与观点帖（CapCut 宣布接入 ChatGPT、11 月公测、交付可编辑时间轴等）按工具上线新闻已剔除。

### Opus 代码动画 6 步：先出 3 秒样片 + 4 行验货命令

**核心提炼**
- 解决什么问题：视频模型"抽卡"式出片，改一处就要整条重抽——Opus 5.5 写的代码，浏览器一帧一帧截下来，再拼成 MP4；画面是代码算出来的，同样的代码每次渲染结果一样，改一处就是改一行再渲染。
- 核心用法：1) 原理三步走：Opus 写一个网页，里面有一个函数，给它一个时间点就画出那一刻的画面；无头浏览器按每秒 30 或 60 帧把每一帧截图；FFmpeg 把几千张截图和代码合成的配乐拼成 MP4 → 2) 代码路线 7 类（据 @xilo2991 入门长文）：Canvas 平面画布、HTML/CSS/SVG、WebGL 着色器、Three.js 3D、p5.js 手绘笔触、HyperFrames/Remotion 视频框架、Manim 数学动画；不用会写这些代码，只要知道名字和对应的画风，告诉 AI 就行；能做扁平插画、像素风、水彩油画、数据图表、产品界面演示，难做真人、写实的具体产品；代码负责"动"，生图模型负责"像"，画面里要有人时交给生图模型出帧、代码负责合成 → 3) 4 条路线对比：A huashu-art-motion（花叔，MIT 开源，5,530 星），36 种艺术风格配方卡、9 种解说语法，配乐也用代码合成，适合要辨识度的艺术短片；B Remotion 官方 Skills（5,790 星），适合文字动效多、数据图表、同一模板批量出片，Remotion 对个人和不超过 3 名员工的公司免费，超过要买公司授权；C Shorts Animator（@tobiadonadon_，免费领取），不用敲命令，解压文件夹，在 Claude Code 或 Codex 里输入 hi，它会自己装好并做一条测试片，适合绘本、油画风的短故事；D 不指定框架，让 Opus 自己选，新手别在提示词里写死"用 Remotion"，它渲染慢、token 开销高，Opus 一般会自己选零依赖的单网页方案；建议第一次做选 C 或 D，想做系列内容再上 A 或 B → 4) 6 步照做（以路线 A 为例，命令来自官方 README）：装 Skill：`npx skills add alchaincyf/huashu-art-motion`，想用 Remotion 就换成 `npx skills add remotion-dev/skills`；装依赖：需要 uv、ffmpeg 和 Playwright Chromium，第一次运行 `uv run --with playwright playwright install chromium`；装好后要新开 Agent 会话 Skill 才会出现；先出 3 秒样片：每种风格只做全片最出彩的那一拍，放进一个网页里挑，整条片子跑完前额度不会白花；选定风格后做完整片，再说"导出成 MP4"；让它回看自己的画面：提示词只占一成，剩下九成是周边工程，最关键的是让 Opus 看自己渲染出的帧再修；它听不见声音，需自己听一遍，告诉它"第几秒不对"，让它单独调 → 5) 可复制提示词要点：用代码做一条 [30] 秒 [竖屏] 动画短片，主题一句话讲清；画风 [水彩绘本 / 剪纸 / 像素风]；先不要做全片，先挑最出彩的一拍做 3 个不同风格的 3 秒样片放进一个网页选片；选定后再做全片，配乐和音效用代码合成；每做完一段抽 6 帧拼成一张图自己检查，有文字出界、叠字、空画面就先修；导出 MP4 后用 ffmpeg 测音轨音量并报数值；不要出现真人和任何品牌 Logo → 6) 出片前 4 行验货命令（作者称已在自己机器上用测试片验证）：看有没有音轨 `ffprobe -v error -show_entries stream=codec_type out.mp4`；测音量 `ffmpeg -i out.mp4 -vn -af volumedetect -f null -`；抽帧拼图一眼看完整条 `ffmpeg -i out.mp4 -vf "fps=1,scale=320:-1,tile=6x5" -frames:v 1 sheet.png`；音量太小就统一响度 `ffmpeg -i out.mp4 -af loudnorm=I=-14:TP=-1.5 -c:v copy -c:a aac fixed.mp4`；作者故意做的极小音量测试片第 2 行测出平均音量 -55.1 dB（基本等于静音），跑完第 4 行回到 -13.3 dB；结论是有音轨不等于有声音，发之前一定测一下。
- 成本与避坑：Opus 5.5 API 官方价输入 4 美元、输出 20 美元每百万 token；@0xMfox 自述一条产品发布片 14 分钟花了 3 美元（作者按官方价估算约 50 万输入加 5 万输出 token，非对方账单）；Shorts Animator 作者称 Claude Pro 档一天能做 50 条以上，作者未验证，Pro 月费 20 美元；接单前清单：Remotion 超过 3 名员工的公司要买授权，花叔仓库里他本人的卡通形象、示范片不随 MIT 授权，别直接拿来商用；别让它画真人、明星和别人的品牌角色，客户 Logo 用原文件贴，不要让 AI 重画；先做 15–30 秒，长片 token 和渲染时间会成倍上涨；中文字体要用可商用的开源字体，比如 Noto Sans CJK；报价按"改几轮"报，不按"生成几次"报，代码片的成本主要在修改，不在出片。
- 什么时候用 / 常见坑：最适合讲解片、产品片、绘本风短片；要真人实拍质感还是交给视频模型；与本库上一条 emil 的"代码即影片"同源但路线、命令与验货不同，独立计入。

**适用场景**：做讲解、产品、绘本风动画短片，想摆脱视频模型"抽卡"、要可复现可修改成片的创作者。

**怎么用它搞钱**：接小店宣传片、知识讲解片、绘本故事代制作（作者转述 @0xMfox 原话：下次有人报 400 美元做宣传片，先发给 Opus 试试）；按"改几轮"报价。

### YouTube AI Video Editing System：提词器 → AI 候选剪辑 → 人工复核 → 设计动画 → 编辑交接

**核心提炼**
- 解决什么问题：YouTube 口播从录制到成片环节散在多个工具里、剪辑决策不可追溯——一套开源工作流把录制、AI 辅助剪辑、设计、动画、最终编辑交接串起来，决策都留在可读的 Markdown 和 JSON 里，方便换自己的 Agent、改规则、手工继续编辑。
- 核心用法（3 条以内）：1) Eyeline 提词器读脚本、跟读声音、录麦克风音频、标口误、记尝试次数，可选局域网同步显示屏；2) Eyeline Edit 复核源 linked 片段、看波形与词时间、调剪切边、重链相机原片、导出视频/音频，AI 工具转写、估算机位同步与漂移、建全片代理、提出候选剪辑并报告可能的转写或切边问题，实验性组装器只写 `plan.candidate.json`、不动正式 `plan.json`；3) 按批准的终剪 transcript 做设计简报与 Claude Design/HTML 板（267 张重塑 HTML 参考板，246 张动画），动画板用时间线 JSON 与本地帧渲染器对齐旁白，再按固定文件夹树 + 批准音频 + 源映射 + 板渲染 + 字幕 + 终剪清单交给 Resolve、Premiere 或其他编辑器。
- 什么时候用 / 常见坑：这是早期公开版，不是无人值守一键编辑器，剪辑决策需要人工复核；语音识别可能把读错的词转写成正确拼写，波形静默不等于词已说完；示例文案、引用与数字需核验或替换后才能用于生产；个人品牌与签名样式已移除，生产前需自己定风格。

**适用场景**：做 YouTube 口播、讲解视频，想把"录制→剪辑→设计→交接"变成可审计工作流的个人创作者和小团队。

**怎么用它搞钱**：接 YouTube 口播代剪辑/频道代运营——同一套工作流换客户复用；或把"提词器 + 候选剪辑 + 编辑交接"做成剪辑服务包。

### LiveEdit：Gemini 驱动的全栈 AI 视频编辑应用

**核心提炼**
- 解决什么问题：想用对话直接分析、剪辑、生成视频，又不想只停留在 Skill 层面——一个全栈应用：React 前端 + Flask API + Celery 异步任务，上传视频后 AI 给摘要、关键事件与剪辑方案，再用 FFmpeg/MoviePy 渲染。
- 核心用法（3 条以内）：1) 上传片段后 AI 聊天（Gemini，可选音频效果）、视频分析（摘要、关键事件、剪辑方案，异步任务）、多片段编辑（按剪辑方案渲染）、视频摄取（上传一次后查询视频、取场景摘要与 Video Intelligence 元数据）、AI Director 会话（围绕创意简报对话，产出结构化剪辑方案并渲染）、图片生成与 AI 视频生成、工作流画布可视化串联步骤；2) 部署：前端 React 19 + TypeScript + Vite，后端 Flask + Gunicorn，Celery + Redis 跑重任务，PostgreSQL 存数据，另需 Logto 登录、Gemini API key 或 Google Cloud Vertex AI 项目、FFmpeg，另有在线演示 https://livedit.space；3) 账号与订阅：Logto 登录、Paystack 支付（KES），后端有 pytest、70% 覆盖率门禁。
- 什么时候用 / 常见坑：自部署门槛高（Python 3.11+、Node 18+、PostgreSQL、Redis、Logto、Gemini/Vertex、FFmpeg 全套），比 Skill 型工具重得多；前端文件夹名拼写为 `LiveEditFronten`（少一个 e），按此名操作；适合先试在线演示再决定是否自部署。

**适用场景**：想搭自己 AI 视频编辑服务的开发者和小团队，或想先在线试用对话式剪辑的创作者。

**怎么用它搞钱**：把 LiveEdit 自部署成面向创作者的剪辑 SaaS，按量或订阅收费；或用它接"AI 分析 + 剪辑方案 + 成片"代工单。
