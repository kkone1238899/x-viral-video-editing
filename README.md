### YumCut

**核心提炼**
- 解决什么问题：想批量做竖屏短视频但不会剪、没时间剪——一句话想法直接变成可发布的 9:16 成片（脚本、配音、画面、字幕自动拼好）。
- 核心用法（4 步）：1) 自部署或直接用托管版 → 2) 输入想法/主题 → 3) 系统自动生成脚本→配音→画面→字幕 → 4) 导出成片发 TikTok/Reels/Shorts；支持多语言、批量渲染，也有 API 供 agent 调用。
- 什么时候用 / 常见坑：适合无真人出镜账号、日更测选题的场景；个人用免费，想拿它给客户做商用服务需要另购商业授权；自部署要自备模型服务，成本自己控制。

**适用场景**：想低成本批量起竖屏账号的个人、代运营团队、带 agent 的内容流水线。

**怎么用它搞钱**：带货短视频代运营。

### cutcli-cookbook

**核心提炼**
- 解决什么问题：手调剪映草稿慢、AI 写剪辑逻辑没法落地——用命令行/JSON 直接生成剪映草稿，桌面版打开就能继续手改。
- 核心用法（4 步）：1) `curl -s https://cutcli.com/cli | bash` 安装 → 2) 套 examples/ 或 templates/ 的 JSON 模板 → 3) `cutcli draft create` 等命令生成草稿 → 4) 打开剪映桌面版，草稿已在列表里，微调后导出；也可以把 prompts/ 丢给 Cursor/Claude Code，让 agent 驱动剪辑。
- 什么时候用 / 常见坑：剪映系模板化剪辑、口播批量生产时用；依赖剪映桌面版；云渲染要配 API key。

**适用场景**：会用 Cursor/Claude Code、想把剪辑变成代码流程的剪辑师和 agent 开发者。

**怎么用它搞钱**：剪辑外包 / 模板卖课。

### FireRed-OpenStoryline

**核心提炼**
- 解决什么问题：手动剪辑太慢、AI 一键成片又没法细改——用自然语言指挥剪辑（"把这段删掉""换个卡点音乐"），每一步可见、可改。

**适用场景**：想对话式剪辑、批量产出统一风格视频的个人创作者和小型团队。

**怎么用它搞钱**：接短视频代运营/批量带货视频单——一次建好 Skill，多客户复用。

### @zhu185178：Opus 5.5 当导演跑通 AI 短剧（挑片与可追溯流程）

**核心提炼**（聚焦挑片/审片环节）
- 让模型先反问再干活：把 1500 字剧本交给模型，它先建项目文件、再追问用途/平台/画风/预算/质量 5 个问题——"先反问后出活"这套逻辑自搭 harness 也能照搬。
- 画风三选一并排看：同一场戏先出 3 张不同画风样图（真人古装、3D 国漫、2D 国风）并排选，避开对"电影感"这类词的理解偏差。
- 角色一致性配方：每个角色一张图里放三视图（胸像特写+全身正面+全身侧面）再加一个辨识特征，解决换镜头换脸。
- 片名字不出错：只靠提示词描述会出假字，首尾帧图片约束让片名四个字一笔不错。
- 挑片两阶段：每段生成 3 条候选，先过硬指标（脸像不像、台词对不对、音量合不合），再谈审美。
- 全程可追溯：每段能看到候选条数、选中哪条、提示词、参考图、首尾帧，方便复盘重做。
- 算总账：全片约 106 美元（文生图和配乐订阅未计入）；单价便宜不等于总价便宜，看整片总账。

**适用场景**：用 AI 生成+人工挑片做短剧/系列短片的个人和团队。

**怎么用它搞钱**：短剧代工的"AI 制片"服务——一次跑通流程，多剧复用。

### @yang_xin19：口播+AI 剪辑涨粉账

**核心提炼**
- 拆开看全流程：选题剧本→拍摄出镜→剪辑（Agent 擅长的脏活：去废词、压停顿、微调语速、推镜、字幕节奏）→包装（B-roll、数据卡片、音效），包装 AI 只能给草案，记忆点得自己定。
- 正确归因："6 分钟剪完"只是剪辑耗时，不是做号总成本——案例博主已稳定更新 3 个月、主页有 5 条爆款打底。
- 不绑一家的口播流水线：粗剪交给规则（去废词、压停顿、自动上字幕），精修留给判断（梗图、何时抛观点留人工）；具体工具只是第三步的可选引擎。
- 发完复盘三个数：点击差→改封面标题；完播差→改节奏和前 15 秒；收藏高→下条把方法写更清楚。
- 算账口径：AI 剪辑工具月费 vs 外包约 80 元/条（月发 30 条约 2400 元）vs 兼职约 6000 元/月——结论是"AI 出粗剪+人过一轮"。
- 决策逻辑：瓶颈是素材堆着剪不动→上 AI 剪辑；瓶颈是出镜和选题→先练镜头。出镜和选题定流量上限，工具把时间成本打下来。

### @msjiaozhu：用 Codex 剪视频——剪映两天的活，动嘴不到一小时

- 解决什么问题：做一条历史/人物故事短视频要经历写稿、配音、对时间、画风统一、剪映推拉，单人一天只能做一条——一句话给 Agent，走"选题策划 → 3 秒黄金钩子 → 爆款正文 → 豆包配音 → 本地毫秒级字音对齐 → 3 套画风分镜生图 → 自动导出带推拉运镜的剪映专业版草稿"全链路。
- 核心用法：1) 文案基于 370+ 篇爆款逐字稿蒸馏出历史叙事风与真实人物故事风；人物故事风节奏为钩子先行 → 巅峰数字 → 可谁也没想到 → 磨难场景 → 金句收尾；钩子库含 A 型数字连排、B 型宿命定格、C 型反常画面等五大类；选定钩子后按事实核查表与字数约束输出，字数误差控制在 ±5%；作者实测更喜欢 Claude Opus 4.6 与 Gemini 3.8 Flash 的文案，尤其 Gemini 3.8 → 2) 配音与对齐：推荐豆包语音大模型，走火山引擎 V3 双向流式 WebSocket 协议，支持 seed-tts-2.0 与声音复刻音色，Agent 用 ffprobe 校验完整性防缺字漏字、文本做哈希防重复扣费；也可自备 voice.mp3；无论哪种音频，都用本地离线工具 Coli（基于 sherpa-onnx）做毫秒级转录，提取每句起止时间戳并对照原文纠偏人名、专有名词 → 3) 分镜 Audio-First：先音频后分镜，以转录时间戳为基准，默认约 8 秒/图，确保从第 0 帧就有图且画面与当时口播情节对应；逐镜做时代考据（人物年龄阶段、时代服饰、发式、建筑形制）；三套画风为 historical-comic（厚涂历史漫画风）、monochrome-narrative（黑白纪实叙事风）、historical-realism（历史写实风）；用正文基准参考图库注入生成工具，首张核验笔触与明暗对比后再批量出图以降低画风漂移 → 4) 剪映草稿：基于 pyJianYingDraft 全自动写入轨道，图片与音频自动复制进剪映草稿目录；平滑慢推拉默认约 16–20 秒走完 12% 幅度；切点冲击缩放为出镜微推近 1.28x 与进镜拉回 1.50x 关键帧，避免剪映自带转场闪黑帧；打开剪映可直接播放、微调、导出 4K/1080P → 5) 字幕：Skill 内未配置带字幕功能，作者强烈建议在剪映里识别字幕，理由是省心且可控。
- 本地复测补充（@superfang119，固定仓库提交 ee25a75，走"自备音频"分支，未测豆包语音与三套画风横向对比）：本地 IndexTTS2 生成配音（单声道、22050Hz、20.262 秒），Coli 转录，imagegen 生成三张厚涂画面，再交给原仓库草稿导出脚本；画面不按总时长除以三均分，而是跟转录结果在"任何人"后取 8.04 秒、在"河边"后取 11.22 秒，三镜为 0–8.04 秒桥头送信人、8.04–11.22 秒藏信近景、11.22 秒以后无人桥头；第二镜只有 3.18 秒，因此关闭该镜的切点冲击缩放，保留简单推拉；方法结论是先定声音再排画面，能回答"这张图为什么在这里换"，但时间戳写到毫秒不代表识别误差只有一毫秒，转录可漏词、错字、错断句，需把识别文本与定稿核对再用对应词句定切点；关键故障是第一次转录包装调用在输出解析阶段报错停住，恢复时保留报错、另存 Coli 实际返回的结构化识别结果，再走原脚本已有的"导入 ASR JSON"入口继续，没有改成按字数估时间，也没有用手写字幕冒充 Coli 结果，作者明确不把这次恢复写成"兼容问题已彻底修复"；参考图结论是三张图都实际传入仓库 HC02 厚涂参考，后两张还另外传入第一张图以延续衣服、信封与河镇气氛，但第一镜与第三镜对比时城门左右位置发生变化，第三镜虽实现"桥头无人"，空间关系只是近似延续，第一张为浓烈夕照、第三张要求晨光但实际仍偏暖亮色，不一定能立即读懂已过一夜，下一轮应先固定桥、城门与河流位置关系，再比较相同构图的日暮与清晨；草稿与预览分开验收：草稿导出脚本用 pyJianYingDraft 把图片与音频复制进工程，按同一份分镜计划写轨道与运镜，价值在于保留可继续修改的工程交接，本地预览渲染得到 1080×1920、30fps、608 帧的 H.264/AAC 视频约 20.267 秒、完整解码检查通过、草稿导出无警告、视频包含音轨，但 FFmpeg 能出视频不等于剪映桌面版已成功打开或导出，本次未完成剪映界面人工打开验收，也未完成独立人耳听审，音文核对与音轨存在检查不能替代读音与听感验收；可复用建议是先用一小段自己的定稿与配音跑出带真实时间戳的分镜，再生成少量图，先确认音文、图意与空间，再扩到长片，有现成素材时也可只开草稿阶段，第一次就做长传记、几十镜、克隆声音、挂车时，出问题很难定位。

### 配音即时钟：先配音、再算每字时间、画面卡词

**核心提炼**
- 解决什么问题：先剪画面再配音、再一点点对，越对越错位——反过来：稿子写好后先生成整篇配音，配音里第几秒说什么就是整条视频的时间表，字幕与画面全跟着它走。
- 核心用法：1) 强制对齐：算出每个字从第几秒开始、到第几秒结束；做法有三种：配音模型自己返回时间、用专门对齐模型算、都没有时把配音拖进剪映用字幕识别（但导出字幕文件要开会员）；作者推荐千问 Qwen3-ASR，0.6B 参数，一张 4G 显存显卡可跑，且已做成 MCP 供模型直接调用 → 2) 画面生成规则：有了每字时间后交给大模型一句一句读稿子，讲数据做图表、讲步骤做流程、引用原话截真网页并划荧光笔、提到产品放 logo；每个动画写成"说到某个词的那一刻，某个东西出现"；画面没有一帧是边播边录的，全按时间一帧一帧算出来，60fps 时第 600 帧画第 10 秒的样子，画完再把配音放回去，电脑卡一下也不会错位 → 3) 导出规格：画面 1920×1080，每秒 60 帧，动画写成一个网页 `产物/动画.html`，网页里提供一个函数 `renderAt(秒)`，传入任意时间就画出这一刻的画面，不要让页面自己往前播放 → 4) 实操文件：文件夹放四份文件——稿子、读法规则、配音设置、画面要求，对话框里只说大白话；实操演示用 DeepSeek + DeepSeek Harness，做一条 15 秒"为什么天空是蓝色的"科普动画；配音设置示例为 ElevenLabs、模型 eleven_v4，API key 放在同一文件夹的 key.txt 里，不要打印出来也不要写进代码文件；作者 key 文件忘填时，Agent 读到空文件后停下来问 key 怎么给，没有接着乱跑。
- 配音选择：不推荐自己录（录音、重录、剪气口、降噪门槛高）、不推荐全网通用机械音（观众记不住、易成营销号）、不推荐克隆别人音色（不花大量时间训练一听就是 AI）；推荐直接选平台自带音色，省时间、效果不差、方便接进 AI 工作流；国产有豆包、千问、MiniMax，开源有 Qwen3-TTS、IndexTTS，作者自己用 ElevenLabs；建议用 API 而非网页生成，因为停顿、情绪、长句断句可由 AI 写进请求，一次生成想要的样子。
- 挑音色方法：Agent 听不到声音，做法是先在平台六万个音色里按中文、女声筛出 60 个，再挑 10 个真的生成一遍，测每个声音的音高与语速，最后把生成声音识别回文字看吐字清不清楚；最后给出四个候选并写语速、音高与特点，作者在备选里挑中了更喜欢的一个，结论是 AI 缩小范围、最终仍要自己听。
- 配音验收：定下音色后先按读法规则改稿，只改了一处——"铺满"换成"布满"，因为"铺"是多音字可能读错；生成完再把配音识别一遍与稿子逐字比对，65 个字全部对上。
- 画面验收教训：第一版画面很空，只有一个小点与几根细线，改一次仍不行，整条就是一个太阳在发光；问题在于只说"好看一点"，Agent 不知道什么叫好看，只会加光效；换成给一份美术分镜（风格、颜色、每个镜头画什么、画多大、卡在哪个字上）并推翻重做；结论是把想要的样子写成它能照着做的规格。
- 什么时候用 / 常见坑：读法规则示例——型号里的数字写成汉字前后留空格（如 GPT-6 写成"GPT 六"）、普通数字保持阿拉伯数字、容易读错的多音字换意思一样的词、两个标点之间超过 26 个字按意思加逗号换气、段落之间空一行读的时候停得久一点；字幕用原稿原文去掉标点，一条字幕是一个短句、在逗号句号处换条、一条不超过 14 个字，每条字幕的出现和消失都卡在时间表里那句话真实开始和结束的时间。

**适用场景**：做科普、讲解类动画短视频，想让字幕与画面精确卡在词上的个人创作者。

**怎么用它搞钱**：接科普/知识动画代制作——"配音即时钟 + 逐词卡点"是一套可报价的流程，按秒或按条收费；或做成自己的科普账号矩阵。

### 代码即影片：TypeScript 故事板 + GSAP + 帧同步音效

**核心提炼**
- 解决什么问题：After Effects 工程改一处就要重做一遍，版本一多就乱——没有 AE 工程，每一帧都是代码：一部片子就是一个文件——故事板，每个场景是几行数据。
- 核心用法：1) 场景为 TypeScript 模块，构建普通 DOM 并用 GSAP 做动画，使用与品牌其余部分相同的缓动曲线 → 2) 浏览器内实时运行，改一行预览就更新，可 scrub 到任意帧；渲染时 Playwright 在无头 Chrome 中打开影片，按一帧一帧推进时钟，把每一帧交给 ffmpeg；示例为 60fps 下 2022 帧，同一份代码可出 1080p 或 4K → 3) 声音也是代码：场景不直接播放音频，而是放置 cue，例如按键声、Agent 流式输出文字时的 tick 声、支付落地时的 tap 声；每个 cue 都是真实录音，离线与帧同步混音；音乐的放置要让最大高潮落在 logo 上 → 4) 与 Claude Code 的协作方法：不写大部分手写代码，而是指导 Claude Code，关键是喂给它"品味"而非指令，例如给它一个喜欢其节奏的参考片段；评审时像设计评审一样提意见，例如"这感觉像有人在点按钮""不要 whoosh 音效""绝不凭空发明颜色"；每条意见都变成它跨会话保留的规则；作者明确表示没有使用任何 Claude skills → 5) 改动成本：改动很便宜，换片中课程只需改一个常量再重新渲染；影片变成像代码一样可编辑的东西，而不是重做。
- 什么时候用 / 常见坑：作者自述这样一部片子约 2 小时工作量、约 60 次调整提示，一条 1 分 30 秒影片的完整 4K 60fps 渲染约 6 分钟，均为作者自述、未独立验证；适合讲解、产品演示类，不适合要真人实拍质感的片子。

**适用场景**：会用 Claude Code、做产品发布片/讲解片、需要反复改版的创作者和品牌团队。

**怎么用它搞钱**：接产品发布片、讲解片代制作——"改一处只改一行再渲染"是报价优势，按改几轮报价，不按生成几次报价。

### CapCut × ChatGPT/Codex：对话式剪辑三轮试跑法

**核心提炼**
- 解决什么问题：有素材不会剪、没时间学剪辑软件——CapCut 公布了面向 ChatGPT 的新插件，从聊视频想法到制作可编辑草稿，再用对话继续改镜头、字幕与音乐，最后进入 CapCut 编辑器精修；但官方发布新闻稿仍把更完整的对话式剪辑体验描述为接下来几个月推进，具体能否使用、开放哪些功能要看账号、地区与版本，不能理解为所有手机端、网页端用户都已可用。
- 核心用法：1) 能力按任务选：已有素材时上传素材或现有草稿组织成片、调整镜头顺序与长度；只有想法时描述主体、动作、风格与画幅生成图像、视频素材并逐步形成草稿，商品外观、人物一致性仍要检查；想找现成样式时按故事用途、风格与节奏找 CapCut 模板再替换媒体继续修改；初稿已做好时继续处理字幕、文字出现时间、配乐、转场与效果，且一次只改清楚一件事以便核对 → 2) 安装与连接检查：官方页面标题用 CapCut × ChatGPT，导航与工作流说明里也用 CapCut × Codex，当前安装说明指向桌面端 Codex 任务，找入口时两个名称都要认清；步骤为在电脑上打开官方产品页 https://www.capcut.com/tools/capcut-x-codex，找到安装提示点 Copy 复制，在桌面端 Codex 任务中粘贴并按当时页面流程完成插件安装，再按提示连接并授权自己的 CapCut 账号——安装完成与账号授权是两个步骤；安装、授权结束后在新任务里确认工具是否可用再开始制作 → 3) 连接验收指令示例："请检查当前 CapCut 插件的连接状态，并列出这个任务实际可用的功能。若支持模板检索，请先检索适合 20 秒旅行短片的模板。暂时不要生成素材或创建视频草稿。"只回复"我可以帮你剪视频"不能证明连接成功；安装失败处理安装，授权失败处理连接，授权成功但当前任务没有工具时先新建任务再检查，不要一上来反复重装 → 4) 第一轮试跑：用自己熟悉的旅行素材做一条约 20 秒、9:16 的社交平台短片，开头放最能交代地点的镜头，中间展示活动，结尾保留一段完整风景画面，只用提供的素材；先给出选片与顺序方案，确认后再制作可编辑草稿与预览，无法读取的素材要明确列出；目标是得到能继续改的项目，只有一份脚本时还不算完成这一步 → 5) 第二轮局部修改示例："在刚才的草稿上，把第二个镜头缩短 1 秒，结尾风景镜头相应延长 1 秒。其余镜头顺序、字幕和配乐保持不变。请返回修改后的预览。"不要只看视频是否仍为 20 秒，还要看被要求保留的部分有没有跟着变化，以此判断后续修改适合继续对话还是直接手动调 → 6) 第三轮编辑器衔接示例："请提供打开当前草稿继续编辑的入口，并列出还需要我检查的问题。我会在 CapCut 中核对字幕、声音和裁切，再决定导出。"打开后检查素材有没有丢失、时间线能否继续改、竖屏有没有裁掉主体；导出分辨率、帧率与可用选项以当前界面为准。
- 什么时候用 / 常见坑：经常把现成素材剪成门店短片、产品演示、旅行记录或活动回顾的人，可优先试选片、排顺序与初稿修改，判断依据是交回来的草稿是否愿意继续往下改；已进入逐帧卡点、复杂合成、精细声音处理的工作，建议比较两种操作成本——一句话能说明白的修改交给对话，拖一下就能完成的细节直接打开编辑器处理；官方产品页提到免费体验入口，但未完整列明全部能力的额度与收费边界，使用生成、素材或导出选项前要查看实际界面，不要推断全部操作无限免费；本条收的是"安装 + 连接验收 + 三轮指令"的试跑法，同期纯新闻与观点帖（CapCut 宣布接入 ChatGPT、11 月公测、交付可编辑时间轴等）按工具上线新闻已剔除。

### Opus 代码动画 6 步：先出 3 秒样片 + 4 行验货命令

**核心提炼**
- 解决什么问题：视频模型"抽卡"式出片，改一处就要整条重抽——Opus 5.5 写的代码，浏览器一帧一帧截下来，再拼成 MP4；画面是代码算出来的，同样的代码每次渲染结果一样，改一处就是改一行再渲染。
- 核心用法：1) 原理三步走：Opus 写一个网页，里面有一个函数，给它一个时间点就画出那一刻的画面；无头浏览器按每秒 30 或 60 帧把每一帧截图；FFmpeg 把几千张截图和代码合成的配乐拼成 MP4 → 2) 代码路线 7 类（据 @xilo2991 入门长文）：Canvas 平面画布、HTML/CSS/SVG、WebGL 着色器、Three.js 3D、p5.js 手绘笔触、HyperFrames/Remotion 视频框架、Manim 数学动画；不用会写这些代码，只要知道名字和对应的画风，告诉 AI 就行；能做扁平插画、像素风、水彩油画、数据图表、产品界面演示，难做真人、写实的具体产品；代码负责"动"，生图模型负责"像"，画面里要有人时交给生图模型出帧、代码负责合成 → 3) 4 条路线对比：A huashu-art-motion（花叔，MIT 开源，5,530 星），36 种艺术风格配方卡、9 种解说语法，配乐也用代码合成，适合要辨识度的艺术短片；B Remotion 官方 Skills（5,790 星），适合文字动效多、数据图表、同一模板批量出片，Remotion 对个人和不超过 3 名员工的公司免费，超过要买公司授权；C Shorts Animator（@tobiadonadon_，免费领取），不用敲命令，解压文件夹，在 Claude Code 或 Codex 里输入 hi，它会自己装好并做一条测试片，适合绘本、油画风的短故事；D 不指定框架，让 Opus 自己选，新手别在提示词里写死"用 Remotion"，它渲染慢、token 开销高，Opus 一般会自己选零依赖的单网页方案；建议第一次做选 C 或 D，想做系列内容再上 A 或 B → 4) 6 步照做（以路线 A 为例，命令来自官方 README）：装 Skill：`npx skills add alchaincyf/huashu-art-motion`，想用 Remotion 就换成 `npx skills add remotion-dev/skills`；装依赖：需要 uv、ffmpeg 和 Playwright Chromium，第一次运行 `uv run --with playwright playwright install chromium`；装好后要新开 Agent 会话 Skill 才会出现；先出 3 秒样片：每种风格只做全片最出彩的那一拍，放进一个网页里挑，整条片子跑完前额度不会白花；选定风格后做完整片，再说"导出成 MP4"；让它回看自己的画面：提示词只占一成，剩下九成是周边工程，最关键的是让 Opus 看自己渲染出的帧再修；它听不见声音，需自己听一遍，告诉它"第几秒不对"，让它单独调 → 5) 可复制提示词要点：用代码做一条 [30] 秒 [竖屏] 动画短片，主题一句话讲清；画风 [水彩绘本 / 剪纸 / 像素风]；先不要做全片，先挑最出彩的一拍做 3 个不同风格的 3 秒样片放进一个网页选片；选定后再做全片，配乐和音效用代码合成；每做完一段抽 6 帧拼成一张图自己检查，有文字出界、叠字、空画面就先修；导出 MP4 后用 ffmpeg 测音轨音量并报数值；不要出现真人和任何品牌 Logo → 6) 出片前 4 行验货命令（作者称已在自己机器上用测试片验证）：看有没有音轨 `ffprobe -v error -show_entries stream=codec_type out.mp4`；测音量 `ffmpeg -i out.mp4 -vn -af volumedetect -f null -`；抽帧拼图一眼看完整条 `ffmpeg -i out.mp4 -vf "fps=1,scale=320:-1,tile=6x5" -frames:v 1 sheet.png`；音量太小就统一响度 `ffmpeg -i out.mp4 -af loudnorm=I=-14:TP=-1.5 -c:v copy -c:a aac fixed.mp4`；作者故意做的极小音量测试片第 2 行测出平均音量 -55.1 dB（基本等于静音），跑完第 4 行回到 -13.3 dB；结论是有音轨不等于有声音，发之前一定测一下。

### Grok Bot 口播剪辑：先调规则再交原片，8 步调教 + 5 步日常

**核心提炼**
- 解决什么问题：口播拍完 2 分钟，后面还要补字幕、做封面、写五套文案——最累的不是剪本身，而是每次都要把同一套要求（字幕别挡脸、logo 不要黑底、音乐别盖过人声）再讲一遍。解法是先把规则一次性写进一个专属 Bot 对话，之后只管拍、只按清单验收。
- 前期调教 8 步：1) 建专属对话：新建一个 Bot 命名为「口播视频」，先说明品牌、内容方向与发布平台，让它复述确认，不明确先问，不要一上来只说「帮我剪好看一点」；先跑通一条短试片再处理长视频 → 2) 上传透明 logo 定品牌素材：用透明底 PNG 原文件，说明水印、封面、片尾各自的用法、位置与大小，品牌文字直接发可复制文本；验收看四角是否露底色、边缘是否发白、缩小后文字是否可辨、水印是否避开人脸与平台按钮；截图/JPEG 通常没有透明底，不能凭预览像透明就认定已抠好 → 3) 把「好看」写成明确画面规则：作者自定 Style A3（奶油色 Liquid Glass 底板、克制卡片、人物小中大景别交替），连同参考图一起给，并写清不接受的元素（霓虹、无意义贴纸、连续缩放），先要一张画面样例再看转场前后几秒，卡片不能盖脸、手机上要读得清；只说「高级感」它只会自行猜测 → 4) 一次说清要交付的文案：每次交付五套——抖音、小红书、视频号、视频号转发、朋友圈，前三平台各给 3 个标题候选，抖音突出问题与冲突、小红书突出步骤与收藏价值、视频号表达清晰稳妥，不编造数据与效果；验收核对每套是否与视频一致、标题是否承诺了视频里没有的结果 → 5) 让音乐给人声让路：人声优先，支持 ducking 就启用（人声出现时降低音乐音量），不支持就手动调低音乐，并说明音乐来源、检查底噪、爆音与结尾截断；验收要戴耳机听一次再用手机外放检查开头、中段与结尾，不要只看时间线有音乐轨 → 6) 动效先限定范围：只做转场、副动效与卡点，主画面继续用 A3，不要用满屏动画替换人物；作者用的 dashi 动效技能是他自己的具体配置，不是所有 Grok Bot 默认具备，先检查是否可用再规定 → 7) 品牌 logo 先核对再叠图：优先找官方来源 logo 并核对品牌与版本，保持比例、只在相关段落出现、避开人脸，找不到可靠素材就列为待补，不要生成近似商标，也不要让画面暗示不存在的合作或背书 → 8) 先做试片一次验收整条流程：用一条短口播跑完字幕、画面、音频、封面与文案，反馈写清时间点、问题与期望（如「00:12 字幕挡嘴，请移到下方安全区」），确认的规则保留成文档，新任务先让它复述规则。
- 日常 5 步：1) 发原片讲清本次要求：上传原始 .mov 或当前支持的视频文件，有逐字稿、补充镜头或参考图就一起提供并说明哪个是最终版本，素材多时按顺序命名；先让它报告能否读取原片、时长、画幅与声音，再给逐字稿与剪辑建议，专名没确认前不要定稿字幕 → 2) 先校专名再做字幕与封面：把人名、产品名、数字、单位与英文缩写单独列出，听不清标出来结合原音核对，不确定标【待核对】，确认后同一份定稿同步用于字幕、封面与平台文案；重点听否定词、金额、日期与品牌名，听写正确不等于事实正确 → 3) 收包要有清单：目标成片 1080×1920 竖屏，另交各平台封面与五套文案，列清文件名与路径，实际支持的话附工程文件，未完成、缺素材、无法导出的项目分别说明；验收要打开实际成片检查首尾、字幕、音画同步与黑帧——预览成功、导出成功、下载成功是不同的验收环节 → 4) 标题选完先审核再发：每个平台选一个标题，把标题、封面、正文与视频放在一起核对，不要在标题里承诺视频没有讲到的结果；指令明确「现在只保存草稿，不发布，不代替我点击发送」，手机上看封面是否读得清，存草稿不等于已发布 → 5) 大文件按用途分版本：区分高清存档版、手机版与分享预览版，列出每版分辨率、时长、大小与用途，大文件走已授权的 Drive 或下载网页并确认权限与链接可用，不要默认公开整个目录；实际下载并打开文件检查画质、声音与链接权限，保留高清源文件。
- 终检清单（作者原清单）：原片可读取、专名与数字已核对、字幕与卡片不挡脸、logo 无底色、人声清楚且 BGM 合适、成片与封面及五套文案齐全、下载文件可以打开、人工审核后再发布。

**适用场景**：固定账号、固定风格做口播的个人创作者和小团队，想把「每次重复讲要求」变成一次调教、多次复用的剪辑规则包。

### Claude Code 做 Motion Graphics：先锁设计系统，再逐镜做 30 秒竖屏

**核心提炼**
- 解决什么问题：客户要一条 30 秒 Reel、周五就要，以前意味着分镜、一天 After Effects、来回三轮改——现在用 React 写、视频自己渲染出来，但如果不先定规矩，模型给的只会是含糊的帧。解法是先写简报、锁设计系统，再逐镜做、逐镜验收。
- 核心用法（5 步）：1) 写图形简报：动代码之前先说清时长、画幅、故事，以及 2–3 条自己真正喜欢的参考视频；含糊的简报只会产出含糊的帧 → 2) 搭 Remotion：提示词示例「Set up a Remotion project for a 30-second 1080x1920 video」，Remotion 把 React 变成真正的 MP4 文件，模型写的是实际的帧而不是对帧的描述 → 3) 锁设计系统：在出任何动画之前，把颜色、字体、缓动曲线与时间节奏写进同一个配置文件，改这个文件整条视频就跟着变；跳过这一步的人，成片一眼就能看出来 → 4) 逐镜做：不要一次要整条视频，一次只做一个场景，在 Remotion Studio 里预览、给反馈、再往下走；这时你是在做艺术指导，不是在写提示词 → 5) 精修再渲染：每个动作都加缓动、入场错峰、加运动模糊、时间对上音乐，然后导出。

### 代理剪辑：把资深剪辑的口味写成 Mini-Skill，再用反馈循环训熟

**核心提炼**
- 解决什么问题：剪辑师还在时间线上一刀一刀抠，代理却已经把产出拉到几倍——但速度从来不是难的部分，难的是口味：如果所有人都喂给 Agent 同样的爆款广告与同样的参考，所有人都会产出同样的视频。解法不是把片子扔给 AI 瞎剪，而是把人的口味写成技能、用人来训。
- 核心用法（Alex Cooper 原帖 11 条，提炼）：1) 99% 的广告现在都应该走代理剪辑，还在时间线里手工剪就是在掉队；作者称其资深剪辑反馈现在每天产出约 5 倍、同等质量——这是单团队体感，不是行业平均 → 2) 正面谈转型的别扭：时间线是剪辑师唯一熟悉的东西，有人会犹豫、有人会担心饭碗；作者认为技术不可避免，但有口味、能训 Agent、能给反馈的人会更值钱，没有的会吃力 → 3) 工具选型主张：Opus 5.5 不用 MCP 或插件就能原生剪全部广告，作者称试过替代方案、没发现明显更好的——这是作者实测主张，未独立核验 → 4) 按风格拆 Mini-Skill：混剪、UGC、AI 动画各做一套，不要塞成一个大杂烩；建法是喂 4–5 条灵感剪辑给 Claude、让它据此生成技能；多 Mini-Skill 是为了让上下文尽可能相关 → 5) 用反馈循环训熟：拿技能把每位资深剪辑最近剪的 25 条广告重剪一遍，放进 artifact，让资深逐条点评，一直循环到技能理解「什么是好剪辑」为止 → 6) 验收标准：训熟后大多数片子 v1 或 v2 就过，偶尔 v3；目标是「几乎不需要反馈」，而不是「能出片就行」 → 7) 只让 A 级剪辑训技能：别人可以跑技能，但不要让口味差的人定标准 → 8) 团队落地分工：AI  champion（作者自认不是团队里最好的剪辑）负责搭 v1 支架然后让开，让最好的剪辑来训技能，而不是自己把技能建完 → 9) 录屏口述理由是最强的提速器：让顶级剪辑开 Gmeet 或 Loom 边剪边讲——为什么切这一刀、为什么是这个节奏、为什么选这段 B-roll，这些推理全部喂进技能 → 10) 给资深留训模型的时间：建、训、打磨技能要经过一段低谷期，不给时间预算，技能只会产出平庸剪辑、省不了多少时间 → 11) 按「这会是视频剪辑最差的一天」来投资：作者认为 Opus 5.5 今天能做大部分剪辑，下一代只会更强，现在练出来的口味与技能库以后只会更值钱。
- 引用链补充（@krpisoweb3，2026-10-28 15:01）：「速度已经解决了，我的 Agent 能剪 5 倍于我的量；速度从来不是难的部分」——执行可以规模化，口味与原创想法才是作品之所以是你的东西；时间线从来不是护城河，提示词也不是。

### 字幕 5 工具按任务选：先定素材状态，再选路线

**核心提炼**
- 解决什么问题：视频剪完了，字幕还在逐句改、逐条对时间——其实可以先让工具生成初稿，把时间留给校对。关键是先分清自己缺哪一步：是缺字幕文件、缺画面文字提取、还是已有字幕要换语言或去掉硬字幕，不必五个全装。
- 5 个工具与路线：1) Subtitle Edit（图形界面，先生成再改准）：改字幕文字、调时间、转格式，也能配合语音识别引擎从音频生成字幕；入门到发布页选适合自己系统的版本，打开视频进 Video → Speech to text，选可用引擎、模型与音频语言再转写；识别后重点检查人名、数字与断句，最后存 SRT；首次用本地引擎通常要下载引擎与模型文件 → 2) video-subtitle-remover（处理已压进画面的硬字幕）：识别字幕区域再用 AI 修补被文字覆盖的位置，适合给自己的旧视频换字幕；提供本地运行路线、无需申请第三方处理 API，但要花本机算力与处理时间，复杂背景与快速运动区域要看实际效果，保持分辨率也不等于能恢复被遮住的原始细节；下载前按操作系统与硬件选包，先拿短片段检查字幕区域再处理长视频 → 3) video-subtitle-extractor（把画面里的字幕变成 SRT）：手里只有视频、没有字幕文件时，让它识别画面上已有的文字，导出 SRT 或 TXT 再校对、翻译或整理；它走本地 OCR、读的是画面里的字，视频没有可见字幕时应当走语音转写路线；文字太小、遮挡、花字与复杂背景都要抽查，别把识别结果直接当定稿 → 4) Translate-Subtitle-File（已有字幕再做翻译，现名「译幕 Zimoo」）：支持 SRT、ASS、VTT，可按配置输出译文或双语字幕；先准备字幕文件，再配置服务商与 API、选源语言、目标语言与输出方式；机器翻译后仍要核对术语、人物称呼与上下文，尤其前后几句连起来才完整的意思；有网页与桌面入口，软件使用条件与翻译服务费用要分别确认，不能把「GitHub 上有项目」理解成翻译全程免费 → 5) auto-subtitle（命令行与重复处理）：用 Whisper 识别视频语音，再用 ffmpeg 把字幕烧进视频，也支持只输出 SRT 先校对再合成；需准备 Python、ffmpeg 与相应模型；中文视频先用 `auto_subtitle "video.mp4" --language zh --task transcribe --model small --srt_only True -o "subtitles"` 只生成字幕文件，再用 Subtitle Edit 打开校对；中文识别不要选名称以 .en 结尾的英语专用模型，这里的 translate 任务是翻成英语，不能当成任意语言互译开关。
- 选路线口诀（作者原结论）：自己录的口播还没字幕，直接试 Subtitle Edit 的语音转写，熟悉命令行也可用 auto-subtitle 先出 SRT 再校对；视频里已有硬字幕、缺少可编辑文件，用 extractor 提取，想换掉旧字时再按需要用 remover 处理画面；已有 SRT/ASS/VTT、需要另一种语言，用译幕翻译后再复核；修改字幕前先把视频剪辑定下来——后续再删一段、变一次速，字幕时间也要跟着调整；保留一份可编辑字幕文件，确认文字与时序以后再决定是否烧进成片。
- 什么时候用 / 常见坑：5 个仓库星数与推送时间均为 2026-10-28 经 GitHub API 核验（见来源行）；auto-subtitle 最近推送为 2024-07-12，属稳定老工具而非活跃更新线，部署前按当前 Python/Whisper 环境实测；Translate-Subtitle-File 的 GitHub API 未返回 LICENSE 信息，商用前自行确认授权。

**适用场景**：做口播、访谈、课程剪辑，需要「转写、改准、提取、去硬字幕、翻译」任一环节的剪辑师和创作者。

**怎么用它搞钱**：接「转写 + 校对 + 翻译 + 烧录」字幕代工单，按分钟或按语言收费；或把「按素材状态选路线」做成字幕服务标准流程包。

### Grok Bot 一台电脑做 MV：节拍分析 → 定装 → 关键帧 → ffmpeg 卡点剪接

**核心提炼**
- 解决什么问题：一支 MV 从分析歌曲、生成画面到剪接输出，全程换软件、换工具最费时间——作者的解法是全程只在 Grok Bot 的电脑上做完，用同一套工具链把「听歌、画图、动起来、剪出来」串成 4 步。
- 核心用法（4 步）：1) 分析歌曲：用 librosa 抓节拍（本例约 108 BPM），再切出主歌、副歌等段落；先用 demucs 把人声分离出来，再试着用 Whisper 辨识歌词——Whisper 听不懂客语，所以最后的歌词是照这首歌在 Suno 公开页面上的客语拼音、由 Grok Bot 转成汉字（转写准确性未经独立核验，客语歌词尤其要人工逐句核对） → 2) 生成画面：用 Grok Bot 内建的 AI 图片生成，先做出三个角色的定装图，再以这三张为基准画出 26 张关键画面，让角色长相前后一致 → 3) 让画面动起来：用 Grok Bot 内建的 AI 视频生成，把关键画面转成 28 段 720p 的动态片段；作者注明已连接的 Krea 与 Higgsfield 这次都没用到，说明「接了不等于用了」，选型以实际出片为准 → 4) 剪接输出：用 ffmpeg 照节拍剪接、放大到 1080×1920、调暖色调，再烧上字幕（思源黑体 Noto Sans CJK TC），加上开场标题和 logo 片尾，最后压缩成 MP4。
- 什么时候用 / 常见坑：这是单支 MV 的实测案例（作者为社区大学 AI 落地应用讲师），数字（108 BPM、26 张关键帧、28 段 720p）都是该案例的实际参数，不是通用标准；720p 生成再放大到 1080×1920，放大不等于原生清晰度，画质验收要看成片而非参数；歌词经「拼音转汉字」一道手，错字风险高于常规转写，成片前必须逐句听对。

**适用场景**：做音乐 MV、歌曲翻唱视频、方言/小语种歌曲视频，想用一套 Bot 内工具链从头做到成片的个人创作者。

**怎么用它搞钱**：接小成本 MV、歌曲宣传片代制作——「节拍分析 + 定装一致性 + ffmpeg 卡点剪接」是一套可报价的流程，按支收费；或把这套流程做成 MV 制作课。

### Opus 代码视频 7 步：先分镜再渲染，让 AI 自检最严重的 3 个问题

**核心提炼**
- 解决什么问题：只给一句提示词就想出电影级视频，得到的往往是千篇一律的渐变背景加淡入淡出——真正厉害的不是那句提示词，而是一套可反复走的制作流程。解法是把视频当成代码工程：写代码、逐帧渲染、检查、再渲染，最后把流程封成 Skill。
- 核心用法（7 步，作者串文提炼）：1) 认清原理：Opus 写动画代码，浏览器逐帧渲染，最后用 ffmpeg 合成 MP4；15 秒、60 帧的视频要生成 900 帧，逐帧可控是代码路线相对视频模型抽卡的核心优势 → 2) 配齐工具链：Claude Code 负责编写、运行与修改代码，Playwright 负责自动控制浏览器并捕获画面，ffmpeg 负责合成视频与音频，Remotion 或 HyperFrames 为可选动画框架；关键一条是让 AI 不只会写代码，还能看到自己做出来的效果 → 3) 提示词要给参考：不要只给一句模糊要求，否则只会得到通用模板；更好是直接提供参考视频，让 AI 先拆解配色、字体、镜头节奏与转场方式，再明确主题、时长、分镜与素材，成片才可控 → 4) 先设计分镜再做动画：作者 16 秒示例按作用分段——开头 2 秒抓注意力、接着 3 秒讲问题、再 4 秒展示产品、再 4 秒证明效果、最后 3 秒收尾；每个镜头都要有作用，而不是单纯堆特效 → 5) 廉价感差在细节：好的动画要模拟真实运动的加速、减速与回弹，而不是从 A 点直线移到 B 点；转场、点击与关键动作还要配上音效，让画面与声音保持同一个节奏 → 6) 最关键是自检：不要第一版就发布；更成熟的流程是让 AI 自动提取关键帧检查画面、检查文字是否清晰、找出最严重的 3 个问题、修改后重新渲染；优秀作品往往经过多轮打磨 → 7) 把流程封成 Skill：把视觉风格、分镜规则、渲染代码与检查流程保存下来，之后做新视频只需按预设格式调用（如作者示例的 `/motion-reel for [URL], 20s, vertical` 式调用），不必每次从零开始。
- 什么时候用 / 常见坑：与本库早档「Opus 代码动画 6 步」同源，但本条新增价值在分镜时间分配、运动与音效同节奏的细节标准、自检「最严重 3 问题」循环与 Skill 封装调用，独立计入；本条串文步骤由浏览器任务在 X 站内逐段核验后带回，首帖之外的分段未再经 fxtwitter API 单独复核；作者结论「值得学的是流程而非提示词」为方法主张，渲染帧数与工具链为作者自述流程，未独立实测。

**适用场景**：用 Claude Code 做讲解、产品、音乐类动画短片，想摆脱视频模型抽卡、要可复现可修改成片的创作者。

**怎么用它搞钱**：接讲解片、产品片代制作——「分镜先行＋自检循环＋Skill 复用」是一套可报价的流程，按改几轮报价；或把封好的 Skill 做成模板包。

### 剪辑选型两分法：生成/编辑模型 vs Agent 剪辑导演

**核心提炼**
- 解决什么问题：剪辑 AI 工具一堆，不知道该为"改片"还是"剪片"买单——先分两类，再按任务选，最后拼成一条组合链路。
- 生成/编辑模型（真正改像素的）：Kling（可灵）O3/4.0 编辑已有素材保真度高，长镜头和运动控制强，适合改光、换风格、延长；Gemini Omni Flash / Veo 3.1 对话式编辑方便，直接说"把背景换成晚上、衣服换红色"就能改，对白和音效同步也不错；Seedance 2.5 单次最长 30 秒，多参考、长叙事镜头表现突出；Runway Aleph 2.0 / Gen-4.5 专业向编辑，较长片段和关键帧控制更稳；Luma、MiniMax H3、Grok Imagine Edit 各有偏科。
- Agent 路线（大模型当"剪辑导演"，本身不生成像素）：Claude Opus 5.5 通过 Claude Code + Skill（HyperFrames、ChatCut、Premiere 桥接等）剪口播、去废片、加动态图形、配音效、粗剪到成片；很多人反馈能搞定 80–95% 的日常工作，作者自述日常内容确实接近这个水平、自己只负责最后约 10% 的微调——该比例为作者实测宣称，未独立核验。
- 传统工具仍占一席：Descript（按文本剪）、OpusClip（长视频切短视频）、CapCut（日常 + AI 功能）。
- 组合结论：生成模型出素材 + Opus 当剪辑导演 + 传统软件做最后润色；复杂叙事或需极致手工的片子仍需自己上手。

**适用场景**：在"买模型还是搭 Agent 剪辑流"之间纠结的创作者和剪辑团队。

### 视频配音 5 项目选型：先试听再选，代码与模型许可分开核

**核心提炼**
- 解决什么问题：稿子写好了，配音却一遍遍重录——一个词念错整段重来，改两句话声音状态还和前一版不一样。解法不是先挑"最自然"的模型，而是先按用途分 5 类、每类试听自己的稿子，再确认许可。
- 5 个项目分工：1) Coqui TTS：多模型语音合成工具箱，提供训练、微调和推理工具，适合研究不同模型、接入程序或搭建本地流程；先选具体模型再看支持语言、运行环境和模型许可，首次安装和下载仍可能需要联网，不能理解成装上就立即离线可用；代码许可与所用模型许可要分别核对；2) ChatTTS：中英文对话式语音合成，关注停顿、语气词、笑声、多说话人；仓库代码 AGPLv3+、公开模型 CC BY-NC 4.0，README 明确限制商业用途，只能作学习与研究，不能直接当商业视频配音工具；3) IndexTTS：B站团队项目，支持参考音频零样本音色克隆，文档还介绍情绪、语速和发音控制；先用自己或已获授权的人声参考试听，参考音频清晰度、背景声和表达方式都会影响结果，不宜把"几秒录音"理解成任何素材都能稳定复刻；采用 B站模型使用协议；4) F5-TTS：提供网页界面和命令行推理，支持输入参考音频、对应文字与待合成稿件，也有分块生成、多风格和多说话人用法；速度要结合硬件、模型与推理配置实测；代码 MIT，预训练模型 CC-BY-NC，商用前需确认实际模型是否允许该用途；5) Qwen3-TTS：CustomVoice 提供预设音色适合先输入文字试听，VoiceDesign 根据文字描述设计声音，Base 可用于参考音频克隆；仓库提供本地 WebUI 与示例，运行仍要准备环境和模型文件，可先看官方演示与文档，不必一开始就下载整套模型。
- 选型口诀：想先找现成声音读稿，看 Qwen3-TTS 的 CustomVoice；想研究参考音色，比较 IndexTTS、F5-TTS 和 Qwen3-TTS Base，先确认许可再用授权录音；想研究对话语气与多说话人，看 ChatTTS 并保留其非商用限制；想做多模型试验、训练或程序集成，再深入 Coqui TTS。
- 试音方法（第一次别扔整篇长稿）：选一小段真实稿件，放进人名、数字、英文缩写和一句较长的话；逐句检查漏字、重复、数字误读、句尾突然加速或停顿不自然；需修改时只重做对应段落，再放回视频确认衔接；克隆音色只用自己或已获授权的人声，商用许可和声音授权分别确认，声音相似不代表可以冒充本人。
- 什么时候用 / 常见坑：文章自述仅核对公开文档，未安装或试听这些模型，不给主观效果排座次，也不沿用历史 Star 排名；"中文最自然"需用同一段稿、相近设置和实际听感比较。

**适用场景**：做口播、讲解、带货视频，不想自己录音、又怕选错配音工具踩许可坑的创作者。

### 数字人口播动作说明书：先蒸馏 3 位博主动作公约数，再让 Agent 执行

**核心提炼**
- 解决什么问题：数字人"假"的毛病通常出在动作描述——提示词只写一句"自然讲解、手势丰富"，模型就把动作频率拉满，结果是手乱比划、手指粘连扭曲、表情和内容脱节、多段拼接跳帧。解法是先给模型一份可量化、可复现的动作执行标准，而不是形容词。
- 全流程（一个 Agent 对话框里跑完动作、对口型、空镜插片、花字和背景音乐，没打开剪辑或 Premiere）：搭配为一个支持 MCP 的 Agent（Claude Code、Codex、WorkBuddy 都行）接任意视频生成模型，本条以 Renoise MCP 为例；Renoise 是一站式 AI 视频平台，接了 Seedance、Kling、MiniMax、Wan、GPT Image、Midjourney、Nano Banana 等约 30 个模型；Renoise MCP 给 Agent 接上工作台，在对话里提需求，Agent 出创意和分镜、调模型生成音画素材，并在云端写代码完成剪辑、字幕和音效，直接出片，还能导出剪映或 Premiere 草稿。
- 第一步：挑 3 位风格错开的真人博主——坐姿冷静的知识类（学稳定的躯干、微小点头和视线停顿）、站姿情绪饱满的观点类（学情绪推高时的手势幅度与重音顿挫）、语速快的资讯或带货类（学利落的手势收放、避免无效晃动）；目的是让 Agent 归纳出"动作公约数"，避免照搬某一个人。
- 第二步：让 Agent 生成标准「动作说明书」，任务提示为"你是口播动作拆解师，忽略长相、服装、音色和背景，只拆肢体、表情和讲话节奏，结果里不出现博主名字"；逐项提取基础体态、手势清单（何种内容时出现、幅度、持续秒数、频率）、头部与视线、停顿、强调方式；再综合 3 位优点整合成给视频模型执行的说明书，只写具体、可量化、可复现的动作，单独列「禁止动作」，并注明哪些来自观察、哪些是建议。
- 原创示例规格（不对应任何真实博主）：坐姿中景（腰部以上），身体向一侧微偏 5 度，双手平放桌面边缘；只在讲步骤序号或核心论点时抬起单手，其余时间归位，手势保持胸口以下、两肩以内，掌心微斜向内，定格 1.5 秒后回落，平均 12–15 秒一次，递进结论时双手可向前微推一次；约 85% 时间看镜头，换论点时视线向右下移开 0.5 秒再回来，陈述句尾小幅低头一次、幅度小于 5 度；逗号约 0.3 秒、句号约 0.6 秒，停顿时双手静止、嘴角微收；禁止动作：手不过下巴和肩、手指不交叉、食指不指向镜头、连续比划不超过 3 秒、不频繁耸肩；作者强调「禁止动作」格外重要，长指令下模型容易发散，提前写死负面约束能减少手指变形、粘连和乱动。
- 第三步：参考图 + 说明书驱动 Agent 自动剪辑成片——参考图选正面或微侧半身照，双手露出、背景干净，可用授权个人肖像，也可用文生图模型生成原创形象；声音可用 Renoise 内置配音，也可上传自己的克隆音频对口型；Renoise 里的 Seedance 2.5 支持原生语音和口型同步，单段最长 30 秒，60 秒左右口播拼两到三段；交给 Agent 的模板要点：形象全片外观和衣着一致、按台词朗读语速适中发音清晰、口型对齐、严格执行动作说明书尤其是禁止动作、每 10–15 秒插一段贴合内容的 B-roll、分段交界处用 B-roll 或推近镜头盖住、加关键词花字字幕和轻音乐、先给分镜和预计积分确认后再生成、输出高清成片另附剪映草稿。
- 接缝技巧：多段拼接的接缝用剪辑解决，不用死磕抽卡；段落交界处切两秒 B-roll，或者把中景切成微特写，观众就看不出光影差异；以前要拖进剪辑软件逐帧贴，现在云端用代码完成切分、字幕卡点、花字和配乐混音。
- 什么时候用 / 常见坑：参考图只用自己有版权的肖像或 AI 生成的原创形象，拆别人只学动作节奏、不克隆脸和声音；发抖音、小红书、B 站等平台按要求标注"AI 生成内容"；说明书调好一次，同系列视频直接套用，每期只换台词和 B-roll 描述；想用自己当数字人时，作者另推荐 HeyGen Avatar 5 模型，能保持人物真实性、效果较好，缺点是价格较贵、可调整性较差；如实标注一个张力点：作者自称只学动作节奏、不拿对方肖像服饰场景，但长文开篇以"产出类似于秋芝、木子、小Lin说等博主的出镜风格视频"为卖点，复用时只取通用动作参数、不碰姓名肖像声音；配套仓库为新仓 0★，方法价值在长文本身，不以星数背书。

**适用场景**：不露脸做口播、知识、带货视频，想让数字人动作看起来像真人而不是"AI 乱比划"的创作者。

**怎么用它搞钱**：接数字人口播代制作——"动作说明书 + 参考图 + 云端成片"是一套可报价的流程，按条或按系列收费；或把"动作说明书模板"做成数字人口播课的核心交付物。

### Claude Code 剪口播十步：从原片到成片的全流程（@Jasper_Jia543）

**核心提炼**
- 解决什么问题：口播原片交给 AI 剪，工具好装、但停顿剪多少、字幕怎么改、什么时候上图解、动效怎么做才不像 AI 做的，这些判断才是难点——作者用 4 条 5 分钟知识口播、十几轮修改沉淀成一套可反复调用的流程，10 万+播放、涨粉过千（作者自述）。
- 核心用法（10 步）：1) 先定对标把"好"变成数字：挑同类账号最新两三条，用无头浏览器每秒截 5 张图并实时测音频，量出换画面频率、真人回全屏间隔、字幕样式、音效密度（对标"小Lin说"实测：讲解段平均 0.7 秒一次画面变化、8–15 秒回全屏 2–6 秒、50 秒一两个音效）；2) 粗剪：Whisper 逐字转录 + ffmpeg 测静音段，0.4 秒以下停顿不剪（换气），句中留 0.26–0.32 秒、整句留 0.34–0.42 秒，省不到 0.15 秒不剪，末句留 1 秒；口误看音量曲线（中间低于 -40 dB 是停顿），切点只在前后 0.1 秒内找最安静处，按整帧裁剪防声画漂移；3) 字幕忠于原话：只改错字、专有名词、明显口误漏字，不确定的 5–10 秒重识别，改动列原文/改后/理由表，白色单行中等偏粗、柔和阴影不描边，断行落词边界；4) 查证：口播里每个数字都搜出处，查不到的不放大不编（《自然》论文"收入提高 20%"是地区相关性估算、非因果，卡片不能写成因果）；5) 结构与版式：三状态（全屏口播/全屏图解+圆形小头像/无人画面），不上下分屏，圆形头像要完整头和头发，卡片不挡嘴和下巴、左右留 80 像素，8–15 秒回全屏、最长不超 15 秒，开头快中段稳结尾加速，先做"内容地图"（每句话标作用再定画面），另写节奏自检脚本查超 8 秒无变化的死区；6) 素材真实有授权对得上：Mixkit 注意 Free/Restricted 两种许可，Wikimedia 只收公有领域/CC0/CC BY/CC BY-SA，新闻论文用原文截图+OCR 定位高亮，同一段素材全片只出现一次，绝不用 AI 生成新闻/现场画面；7) 设计与动效：频道外观统一但不僵化，AI 味黑名单（激光条、扫描线、取景框、REC 计时、故障闪切、简单几何线条、扁平色块），参照数码产品/苹果广告（毛玻璃卡片、金属感字、柔和分层阴影），动效弹簧缓动带一点点过冲，关键词说到那一刻才光扫+下划线，另附踩坑对照表（金字发灰关 text-shadow 改 drop-shadow、金底金字改深色小块配浅色字等）；8) 声音以音乐为主、音效要少：配乐全程铺着、比人声低 8–10 LU，人声时自动让位，选曲先下载三四首测响度起伏/能量曲线/低频，明显音效每分钟几个且落在真实动作上，成片 -16 到 -14 LUFS、峰值不超 -1 dB，选曲听感必须自己戴耳机听一遍；9) 渲染前自检：24 条必过项 + 100 分评分表，必过全过且 85 分以上才允许渲染，三层检查（节奏自检脚本/渲染工具自带检查/逐张截图拼总表放大看），另开一个 agent 来审（主 agent 会脑补）；10) 渲染和交付：测响度峰值、抽 8 帧拼图确认与预览一致，交付说明含成片路径/时长/响度、每处修改及原因、剪辑结构、事实核对与来源、素材授权清单、字幕改动、没做到的地方及需亲自确认处，文件名带版本号、旧版全保留。
- 工具层：Claude Code 当总监（读转录、修字幕、查证、排结构、找素材、写剪辑方案和动效代码、截帧自检），mlx-whisper 本地逐字转录，ffmpeg 处理声音切点响度，HyperFrames/Remotion 写画面渲染成片；核心原则是把错误挡在渲染之前（方案里发现的错不留到截图，截图发现的错不留到渲染），AI 看不到动态听不到声音、没看过听过的要明说。
- 规则沉淀：每条意见做三件事——记进要求文档（哪个画面、为什么不行）、找根本原因改通用代码样式、变成必过项或自动检查（"上下分屏视觉重心不好"提过一次，之后所有片子都不再分屏）。
- 什么时候用 / 常见坑：知识类口播最对味；渲染一次约 20 分钟，检查前置才省时间；全文提示词在原文中，照抄前先按自己对标账号改数字。

**适用场景**：做知识类口播、想用 Claude Code 把剪辑变成可复用流程的创作者。

**怎么用它搞钱**：接知识口播代剪辑——"对标量化 + 渲染前自检 + 交付说明"是一套可报价的流程，按条收费；或把这套流程做成口播剪辑课。

### 8 个免费工具搭 Claude 视频栈（@ellypromtstar）

**核心提炼**
- 解决什么问题：Claude 会写动效，但不会剪片、配字幕、配音、配乐和质检——作者把 8 个免费工具锁成一条"Claude 写、工具链执行"的流水线，每件工具都附"哪里会坏 + 怎么查"。
- 核心用法（8 件 + 梯子）：1) Remotion：Claude 写 React 组合，本地渲染成帧，坏在 Claude 会编不存在的 API，查法是渲染前跑 `npx remotion compositions` 看 id 在不在；2) Whisper：逐词时间戳做烧录字幕（本地或免费 CLI），坏在静音/音乐段幻觉出词，查法是边听边对 JSON、没声音的词先删；3) Kokoro/本地 TTS：旁白免费离线，坏在数字、网址、品牌名被赶着念过去，查法是脚本里把品牌按读音拼写、"100M+"只在口播时展开；4) Freesound CC0：配乐音效零授权费，坏在下成 CC-BY 忘了署名或错拿非 CC0，查法是导出前重开下载页核对许可行；5) three.js：浏览器里单 HTML 文件做产品旋转/粒子/Logo 动画、不用安装，坏在 Claude 编一个不存在的 GLB 链接导致黑屏，查法是开 DevTools 看 Network、有 404 就先换程序化几何体；6) 开源 Claude skills：短 Markdown playbook、每次加载，坏在写成长篇小说 Claude 只执行一半，查法是 kept under ~40 行、两周没触发的规则就删；7) ffmpeg 切片表：Claude 不擅长 timeline GUI、擅长写 cut list，静音删除、重构、拼接、烧 ASS 全免费，坏在时间戳四舍五入切到词中间，查法是把切点贴回带帧显示的播放器、打到音素就前后挪 ±3 帧；8) Playwright QA：打开 Remotion Studio/three.js 页/渲染预览截图，坏在只查"页面加载了"不查"动效看得见"，查法是对内容断言、不对状态码断言（五张黑帧也算失败）。
- 梯子顺序：skill 定规则 → Claude 出草稿（Remotion/three.js）→ Kokoro 配音 → Whisper 字幕 → Freesound 配乐音效 → ffmpeg 切/缩放/烧录 → Playwright 截图 QA → 发布；缺哪一环就跳过哪一环，但 QA 永不跳过；开工前提示词清单：定格式（Remotion/three.js/ffmpeg 三选一）、尺寸 1080×1920、时长、首帧即 payoff、品牌色、首帧上钩子文案、不编没给过的数字、不用付费 API/图库链接/假素材路径、结尾写"哪里会坏 + 怎么查"。
- 什么时候用 / 常见坑："10 个账号一周 1 亿+播放"为作者自述、未独立核验；每件工具的"坏点"都是作者实测踩过的，比工具清单本身更值钱；附带的粘贴即用提示词在原文中，照抄前先改品牌色与尺寸。

**适用场景**：用 Claude Code 做竖屏短视频、想把"写动效→成片→质检"串成免费工具链的创作者。

**怎么用它搞钱**：接"Claude 视频栈搭建 + 批量出片"单——先帮客户把 8 件工具与 QA 梯子跑通，再按条收代剪费。

### 说一个词，Claude 就剪掉失误（@Casanova_Brooks）

**核心提炼**
- 解决什么问题：录口播说错就得重录整段，剪一条 YouTube 视频要占掉整个周六——作者让 Claude 按自己写下的规则剪片，23 分 39 秒原片出 18 分钟成片，83 刀全由 Claude 选。
- 核心用法：1) 录制时说错只说一个词"edit"继续录，Claude 听到后自动定位并切掉该段；录制时在手机拍一张白板、写下不想要的内容，Claude 读图理解；2) 剪辑规则写死：删口头禅（um/uh）、半途而废的句子、重录的句子、开场白与清嗓子；绝不删重复（防断句）；钩子规则——视频永远以标题承诺开场，第一句没说承诺就把后面说承诺的那句移到最前面；3) 流程：原片丢进 Google Drive 文件夹，Agent 每分钟检查一次，新片来了就开云电脑干活（转录、剪辑表发到手机）；剪辑表列每一刀的起止与原因，末尾附剪完的干净 transcript（可复用做音频或博客）；每版顺序编号、原片与成片都保留；4) 手机改片：预览发到 Telegram（带剪辑表与改动说明），回复一句"change that"就改，改完出新版（v1 误删了一句想保留的话，v2 加回来；40 秒处开场太 abrupt，加了一个 fade to black）；改完批准，成片进 YouTube Drive、一键上传。

### 1 分钟 UGC 广告的 5–6 小时花在哪（@simulart，引用 @spwfeijen）

**核心提炼**
- 解决什么问题："$2 一条 clip"是真的，但不是一条广告的成本——作者剪 Seedance 做的 Everyday Dose 口播 UGC，生成是最快的一环，1 分钟广告仍要 5–6 小时，时间花在四处。

- 结论：两张参考图就能做出一张会说话的脸，但把人带到产品镜头前的是剪辑；省时、省力、省钱三者只能占其二。

**适用场景**：做 AI 生成口播 UGC 广告、想算清"生成便宜、剪辑贵"这笔账的创作者与广告主。

### faster-whisper 本地转字幕实测：先转 wav 再转录（@Guangquan66）

**核心提炼**
- 解决什么问题：本地给口播视频自动出字幕草稿，不想每月交语音 API 的钱——作者在没填模型 Key、没开云端语音接口的 Linux 云电脑上，把 SYSTRAN 开源的 faster-whisper（26,541★、2,215 fork、MIT）装进本地虚拟环境，亲手实测十步。
- 核心用法（10 步实测）：1) 虚拟环境里装：`python3 -m venv` + `pip install faster-whisper`，装到 1.2.1（顺带 ctranslate2 4.8.5、av 19.0.2——后一个版本号很关键）；2) 先核对仓库数字：发文前用 GitHub API 现查星数，不抄别人卡片；3) 直接读 mp3 会炸：把 mp3 路径丢给 `transcribe` → `TypeError: metadata_errors`、EXIT=1（faster-whisper 1.2.1 的 `decode_audio` 还在给 PyAV 传 `metadata_errors=`，而 pip 拉到的 av 19.0.2 已不认这个参数；装成功 ≠ 路径能直接转）；4) ffmpeg 先转 16k 单声道 wav：`ffmpeg -y -i 输入 -ac 1 -ar 16000 输出.wav`，再用标准库 wave + numpy 读成 float32 数组喂进去，不再走有 bug 的路径解码；5) 中文口播 + tiny：17.33 秒音频推理 0.457 秒能出字，但错字多（"口播"→"口波獎"、"字幕"→"出自目"、专有名词糊掉、名字写错），tiny 适合先出一版草稿、不适合直接当终稿；6) 换 base 模型：加载变慢（load 4.099 秒含首次下载）、句子清楚很多（"口播"对了），日常建议先 tiny 试通路、正式字幕用 base 或更大，CPU 上 base 加载比推理贵；7) 英文会议短音频 tiny 就很能打：10.49 秒音频推理 0.325 秒、三句几乎全对；8) 静音文件出空文件：3 秒纯静音 EXIT=0、输出 0 字节——没声音就别硬编字幕，比瞎编一句可靠，开 `--vad` 同样是空文件；9) 语言选错会一本正经胡说：同一段中文口播强制 `--language en`，出来"the first melody is called Fester whistle"，命令成功 ≠ 内容可信，不确定语种宁可自动检测、或先听 3 秒再设 `--language`；10) 中英夹杂一句：英文半句往往比中文半句稳（"排期"→"排棄"、"群里"→"群力"，英文全对），终稿仍要人工改专有名词和近音错字。
- 最短路径（5 步）：建 venv → `pip install faster-whisper` → 直接读 mp3/mp4 报 `metadata_errors` 就先 ffmpeg 转 wav → wav 读成 float32 再 `WhisperModel("tiny", device="cpu", compute_type="int8").transcribe(array, language="zh")` → 中文先 tiny 通路、定稿换 base，语言参数别瞎填。
- 什么时候用 / 常见坑：只用 CPU + int8，没开 CUDA、没填 Hugging Face Token；没跟 openai-whisper 原版对打 WER，也不编"快 4 倍"这类百分比；没接 WhisperX 说话人分离、没接字幕烧录成 srt 的完整剪辑链；浏览器报告所列后五步（烧字幕/对齐/B-roll/转场/封面）在原文中不存在，本条以 API 原文十步为准；流水线库另有一篇 faster-whisper 实测（@zdt0403，2026-11-02，热词表方向），与本条角度不同。

**适用场景**：要把会议录音、口播、英文参考视频先变成可复制文字/字幕草稿，又不想每月交语音 API 钱的创作者。

**怎么用它搞钱**：接"会议/口播转写 + 字幕草稿"单——按"本地免费转录 + 人工校对专有名词"打包，按分钟或按条收费。
